## Design (must NOT copy the dark-teal/purple color scheme, even though it also has a 3D avatar)
Go for a distinct visual identity:
- Light-first or high-contrast editorial theme (off-white/cream background, deep navy or ink-black text, one confident accent color like amber, burnt orange, or deep green — NOT teal/cyan/purple)
- Typography-led design: large serif or geometric-sans display headlines, monospace accents for tags/labels/section numbers (fits a backend/systems engineer identity)
- Card-based layout with sharp/minimal borders rather than glassy/glowing dark-mode cards
- Fully responsive (mobile-first)
- Smooth scroll + scroll-triggered fade-in animations for sections

- Include a 3D character in the Hero section, rendered with React Three Fiber (`@react-three/fiber`) and `@react-three/drei` for helpers (OrbitControls disabled/limited, useGLTF loader, etc.)

- Load it with `useGLTF('/models/avatar.glb')` and render it in a `<Canvas>` positioned next to/behind the hero text (similar layout weight to a typical hero-character composition, but NOT the same color grading)
- Lighting/color grading: warm rim-light (amber/orange tones) instead of cool teal/cyan, to match the site's accent color — use directional + ambient lights, avoid neon/glow post-processing
- Animation states:
  - Idle loop: subtle breathing/sway motion (simple procedural bob via `useFrame`, since Ready Player Me exports may not include custom animation clips)

- Make the avatar component isolated (`components/Avatar.tsx`) and lazy-loaded / dynamically imported with `next/dynamic` (`ssr: false`) since Three.js requires the browser
- Add a graceful fallback (static image or simple placeholder) if the `.glb` fails to load, so the build doesn't break before I've added the model file
